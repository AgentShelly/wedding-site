TRANQUILO VACATION RENTALS — BUILD SPECIFICATION
================================================

PROJECT NAME: tranquilo-web
TARGET DOMAIN: tranquilovacationrentals.com
LAST UPDATED: 2026

How to use this document: paste this entire file into Claude Code or Codex
as the initial brief, then iterate page by page. The image assets will be
delivered later inside a folder named "assets-in/" at the repository root.


1. GOALS AND NON-GOALS
----------------------

GOALS

Build a fast, secure, accessible, SEO-optimised marketing site for a small
vacation rental business operating in Playa Del Carmen, Mexico. The site
must showcase ~19 properties, capture qualified inquiries, and deep-link
to external OTAs (Airbnb, VRBO, Booking.com) for actual reservations.

The site must achieve Lighthouse scores of 95+ on Performance, 100 on
Accessibility, 100 on Best Practices, and 100 on SEO across mobile and
desktop. Largest Contentful Paint under 2.0 seconds on 4G mobile.
Interaction to Next Paint under 200 ms.

The site must be bilingual: English (default) and Spanish.

NON-GOALS

Do NOT build user accounts, registration, login, password reset, or a
shopping cart. These existed in the legacy WordPress site and are removed.

Do NOT build a custom payment engine or hold credit card data. Bookings
finalise on third-party OTA platforms.

Do NOT build a CMS in v1. Property data lives in versioned content files
inside the repo (see section 7). A CMS can be added later if needed.


2. TECH STACK (LOCKED)
----------------------

Framework: Next.js 15 (App Router) with React 19 and TypeScript 5.
Styling: Tailwind CSS v4 with CSS variables for theme tokens.
UI primitives: Radix UI for accessible dialog, popover, dropdown, accordion.
Icons: lucide-react.
Fonts: next/font with one display font (e.g. "Fraunces") and one body
       font (e.g. "Inter"), self-hosted, subset latin and latin-ext.
Image handling: next/image with AVIF and WebP, plus a static loader.
Forms: react-hook-form + zod for client+server schema validation.
Email delivery: Resend (transactional API).
Anti-spam: Cloudflare Turnstile (free, GDPR-friendly, no Google).
i18n: next-intl, default locale "en", second locale "es".
Date handling: date-fns (no moment.js).
Analytics: Plausible Analytics (privacy-first, cookieless) OR Vercel
           Analytics. Pick one and stick to it.
Markdown for blog: MDX via @next/mdx with remark-gfm and rehype-slug.
Hosting: Vercel (Production + Preview deployments).
DNS, WAF, CDN, bot mitigation: Cloudflare in front of Vercel.
Package manager: pnpm.
Node version: 22 LTS (pinned in .nvmrc and engines field).

Linting and formatting: ESLint with next/core-web-vitals and
typescript-eslint, Prettier with the tailwindcss plugin, Husky pre-commit
hook running lint-staged.

Testing:
- Unit/component: Vitest + React Testing Library.
- E2E: Playwright covering homepage, properties list, property detail,
  contact form happy path, and 404.
- Accessibility checks in Playwright via @axe-core/playwright.

----------------

The visual identity is "tranquil, warm, coastal, modern Mexican". Avoid
generic AI-template aesthetic.

Use Tailwind's @theme directive to map these to utility classes such as
bg-ocean-500, text-ink-900, border-line.

TYPOGRAPHY

Display: Fraunces, weights 400/600, used for h1 and h2 only.
Body: Inter, weights 400/500/600, used everywhere else.
Base size 17px on desktop, 16px on mobile. Line-height 1.55 for body,
1.15 for display.

SPACING

Use Tailwind defaults plus a section padding scale: --space-section-y on
mobile = clamp(3rem, 6vw, 5rem), on desktop = clamp(5rem, 8vw, 8rem).

RADII

Cards: 16px. Buttons: 12px. Inputs: 10px. Images inside cards: 12px.

SHADOWS

Subtle only. shadow-sm for cards at rest, shadow-md on hover. Never use
heavy drop shadows.

MOTION

All transitions 150-250 ms ease-out. Honour prefers-reduced-motion: cut
all non-essential motion to 0 ms when the user has set that preference.

  /assets-in/hero/homepage.jpg, ...
  /assets-in/blog/[slug]/cover.jpg, ...

Build script /scripts/process-images.ts uses sharp to:
- Resize each property photo to 1600w, 1200w, 800w, 400w.
- Encode AVIF (quality 60) and WebP (quality 75).
- Strip EXIF.
- Output to /public/img/properties/[slug]/[index]-[width].[avif|webp].
- Generate a content-hashed file name for cache busting.
- Write a manifest JSON at /content/image-manifest.json mapping slug to
  the produced files with dimensions, so the Property content files can
  reference logical names while next/image sees real paths.

Add npm script "images" that runs this on demand. Hook it into the build
pipeline only when /assets-in changes (check via a checksum file).

Every image MUST have descriptive alt text in the property content file.
Decorative-only images (background, divider) use alt="".

A favicon set (16, 32, 48, 180 Apple touch, 512 maskable PWA) is
generated from /assets-in/brand/favicon-source.png by a small script.


9. FORMS, API, AND EMAIL
------------------------

Endpoint: POST /api/inquiry

Request body (JSON), validated with zod:
  name: string, 2-100 chars
  email: valid email, lowercased
  phone: optional string, 6-30 chars
  checkIn: ISO date, today or later
  checkOut: ISO date, after checkIn, max 365 days out
  guests: { adults: int 1-20, children: int 0-20, infants: int 0-10 }
  propertySlug: optional string matching a known property
  message: string, 10-2000 chars
  locale: "en" | "es"
  turnstileToken: string

Server logic:
1. Validate body with zod. Reject with 422 if invalid.
2. Verify Turnstile token via the Cloudflare siteverify endpoint using
   TURNSTILE_SECRET_KEY env var. Reject with 400 if not human.
3. Apply rate limiting: max 3 submissions per IP per 10 minutes and 10
   per IP per day. Use Upstash Redis (UPSTASH_REDIS_REST_URL and
   UPSTASH_REDIS_REST_TOKEN) with @upstash/ratelimit. Respond 429 when
   exceeded.
4. Sanitise the message field (strip HTML, normalise whitespace).
5. Send two emails via Resend:
   a) To the owner (hello@tranquilovacationrentals.com): subject
      "New inquiry — {propertyName or 'General'} — {checkIn} → {checkOut}".
      Include all fields in a clean HTML template plus a plain-text fallback.
   b) To the guest: subject "We received your inquiry — Tranquilo Vacation
      Rentals". Confirmation copy in their chosen locale.
6. Log a record of the inquiry to a private Notion database OR an
   Airtable base via webhook (configurable). If neither configured, skip.
7. Respond 200 with { ok: true, id: "<uuid>" }.

Error responses always JSON, never leak stack traces. All errors are
caught and logged via console.error so they show in Vercel logs.

CSRF protection is unnecessary for fetch-based JSON POST from same
origin when SameSite=Lax cookies are not used for auth — but still add
an Origin check: reject requests whose Origin header does not match
the deployed domain.


10. SECURITY
------------

Headers (set in next.config.ts and middleware.ts):
  Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
  Content-Security-Policy: see below
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=(),
                       interest-cohort=(), payment=()
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Resource-Policy: same-site

Content-Security-Policy (strict, nonce-based for inline scripts):
  default-src 'self';
  script-src 'self' 'nonce-{NONCE}' https://challenges.cloudflare.com
             https://plausible.io;
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob: https://*.tranquilovacationrentals.com;
  font-src 'self';
  connect-src 'self' https://plausible.io
             https://challenges.cloudflare.com;
  frame-src https://challenges.cloudflare.com;
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
  upgrade-insecure-requests;

Generate a CSP nonce per request in middleware.ts and pass it to scripts
through React context or the `nonce` prop on <Script>.

All secrets via Vercel Project Environment Variables. Required:
  RESEND_API_KEY
  RESEND_FROM_EMAIL                  (e.g. "no-reply@tranquilovacationrentals.com")
  OWNER_EMAIL                        (hello@tranquilovacationrentals.com)
  TURNSTILE_SITE_KEY                 (also exposed as NEXT_PUBLIC_TURNSTILE_SITE_KEY)
  TURNSTILE_SECRET_KEY
  UPSTASH_REDIS_REST_URL
  UPSTASH_REDIS_REST_TOKEN
  NEXT_PUBLIC_SITE_URL               (e.g. "https://tranquilovacationrentals.com")
  NEXT_PUBLIC_PLAUSIBLE_DOMAIN
  NOTION_API_KEY                     (optional, leave empty if unused)
  NOTION_INQUIRY_DB_ID               (optional)

Other security measures:
- Dependabot or Renovate enabled in GitHub for automatic dependency PRs.
- pnpm audit passes with no high or critical findings; build fails on
  high+ via CI.
- All third-party SDKs loaded with next/script strategy="lazyOnload"
  or strategy="afterInteractive", with subresource integrity where the
  CDN supports it.
- No third-party iframes except Cloudflare Turnstile.
- All outbound links rel="noopener noreferrer".
- Form inputs use autocomplete attributes correctly.

12. SEO
-------

  generateMetadata() with title, description, canonical, og:image,
  alternates (hreflang en, es, x-default).
- robots.txt allows everything except /api/, generated.
- sitemap.xml generated by next-sitemap, includes every locale variant
  with hreflang annotations.
- JSON-LD on:
  - Site-wide: Organization, LocalBusiness with NAP, ContactPoint.

  - Each blog post: BlogPosting with author and datePublished.
  - Breadcrumbs on every non-home page.
- Open Graph image generation: an /opengraph-image.tsx route per page
  rendering a 1200x630 image using the OG image API.
- Canonicals point to the English URL with hreflang to Spanish.

  /listings/:type   -> /types/:type
  /area/:area       -> /areas/:area
  /city/:city       -> /stays?city=:city
  /features/:slug   -> /stays?amenity=:slug
  /action/:slug     -> /stays

  description has { en, es } fields).

- Language switcher preserves the current path.
- All dates formatted with the locale, currency formatted with USD
  Intl.NumberFormat.

17. CI / GITHUB ACTIONS
-----------------------

Workflow on every push and PR:
1. pnpm install --frozen-lockfile
2. pnpm lint
3. pnpm typecheck
4. pnpm test (unit)
5. pnpm build
6. Run Playwright e2e against the built app (CI mode).
7. pnpm audit --prod --audit-level=high
8. Upload Playwright HTML report as artifact.

On main, additionally:
9. Lighthouse CI against the Vercel preview, asserting category scores.
