# Acceptance criteria — proposed static album release

Date: 2026-11-02. The static design and local synthetic implementation are approved. Production/account checks below have not passed unless local evidence explicitly states otherwise. Evidence must be recorded under `review/validation/` with command, result, timestamp, environment, release/input digests, target IDs, scope of authorization and limitations. Private data/large artifacts stay in an approved protected external location. Thresholds marked **P** remain proposals requiring explicit approval; none is a verified baseline. Approval criteria and separate action gates still apply if every technical test passes.

| ID | Measurable requirement | Required evidence / failure action |
|---|---|---|
| AC01 Clean checkout | Fresh checkout of approved commit + lockfile, documented Node/npm/CLI versions, only approved manifest external input. Install/typecheck/lint/static build exit 0 under separately authorized execution. No undeclared machine paths/local secret dependency. | Exact commands/log summary; old `next lint` repaired before claiming lint. Inspect static export for absence of server API/functions and runtime secret reads. No command was run here. |
| AC02 Explicit target safety | Missing/wrong team/project/store/environment fails before any mutation. Preview default uses explicit preview target and a different allowlisted project/store. Test first-deployment case. Production requires separate recorded approval and stages without assigning aliases. | Negative cases against stub CLI; later real metadata verification in authorized target. **0** wrong-target network mutations. |
| AC03 Repeat-run stability | Apply same release+digest twice; second verifies/reuses receipt/deployment. Same release ID with changed inputs fails. Counts and IDs of stores/projects/databases/domains unchanged by routine apply. No database created. | Before/after resource metadata; stub timeout-after-acceptance reconciliation plus isolated live repeat check if authorized. If remote outcome unknown, no resubmit. |
| AC04 Drift | Inject target/binding/domain/trigger/config/manifest changes; check reports specific drift, exits nonzero for safety-critical differences; no reset. Plan older than **15 minutes P** rechecks. | Sanitized diff, 0 corrective mutations. Unexpected dependency/db blocks release for review. |
| AC05 Concurrency | Two local applies: exactly one obtains lock. Cross-host/unknown remote mutation or missing owner lease blocks apply. Simulated crash/stale lock needs manual reconciliation. | Native-process test plus documented one-operator/host lease, disabled alternate triggers and remote preflight fingerprint. No claim of a distributed lock. |
| AC06 Secret safety | Canary secrets in mocked env/CLI error output absent from logs, plan, receipt, HTML/JS, source upload and review evidence. Production tokens absent from preview. | Scan built artifact and captured logs with canaries; inspect upload file list. **0** leaked canaries/real secrets. Do not print secret values as proof. General historical secret cleanliness remains unverified. |
| AC07 Static core E2E | Guest opens `/gallery` from `/` and `/photos`, sees seven albums with expected counts, filters, opens/closes lightbox, views and downloads unchanged original bytes. Fresh mobile and desktop browser, keyboard navigation, labelled controls, Escape/focus return on dialog. | Synthetic fixtures covering current/legacy paths, missing thumb, text escaping and unsupported-format original download. 100% named journey checks pass. No requirement to decode HEIC in every browser; download works and failures are explicit. |
| AC08 Retired features | Upload/name capture/admin controls absent. New deployment POST upload/login/delete returns 404/405; ZIP/export/admin routes do not expose a privileged feature. Legacy deployed writers also unusable after approved freeze/token retirement. | Route checks + owner credential/old deployment inventory; verify issued-upload-token lifetime handled. **0** production write probes; test mutations only synthetic in isolated environment. |
| AC09 Snapshot completeness | Two complete inventories after write freeze agree on all paths/sizes/available integrity metadata. Every original from `photos/` is represented once; legacy mapping and thumb fallback correct. No production object deleted/overwritten/renamed. | Protected full inventory, public manifest digest and count; source-store ID; zero unresolved list pages/errors. Manifest max **5 MiB/5,000 originals P**; exceed → explicit design review, no truncation. Audit's 167 objects is not an expected photo count. |
| AC10 Data/compatibility | Same production store identity, public hosts and object paths before/after lifecycle; all object metadata counts/sizes unchanged while frozen. Byte integrity for owner-authorized inventory/backup plus sampled existing originals; no intentional data loss. | Provider transfer continuity confirmation and pre/post inventory; all-byte hash comparison if bytes are downloaded. State exact sampling limits; do not claim full byte proof from metadata alone. Unexpected difference blocks cutover and starts reconciliation. |
| AC11 Failed health | Inject missing/malformed manifest, partial pagination, corrupt digest, dependency 403/404/timeouts, empty production snapshot, wrong deployed ID or absent asset. Candidate never promoted. | Stub/local failure tests and isolated health rehearsal; alias unchanged, nonzero exit, sanitized partial receipt. Valid explicitly empty fixture is distinguishable from failed read. |
| AC12 After-promotion recovery | Simulate failure with preauthorized compatible static rollback; verify original production alias restored and album usable. If rollback target invalid/unavailable, stop and escalate; never “rollback” bytes or transfer automatically. | Rehearsal in isolated environment + approved production recovery plan; document token-invalid dynamic deployments ineligible, alias auto-assignment side effects and limits. No production rollback test authorized now. |
| AC13 Bounded execution | Safe reads at most 3 attempts, **10s/attempt, 30s total P**; build/deploy polling **20min P**, promotion/rollback status **3min P**, health **2min P**. Timeout preserves unknown remote state and lease, no blind mutation retry. | Fake delays/429/auth failures/disconnect/SIGINT tests. No required unbounded waits. Remote continuation after CLI timeout explicitly reconciled. |
| AC14 Quota/budget | Zero total recurring/one-time service charges for album in selected account scope, no paid add-on/seat/trial expiry/automatic upgrade. Confirm Hobby eligibility, actual plan/limits/shared usage and outstanding source obligations. Only low scenario proposed for free operation. | Owner redacted billing/usage/plan evidence and written quota-exhaustion policy. Current Pro evidence fails this gate. Do not infer future zero bills from one snapshot; verify first complete post-change billing period before claiming realized cost. |
| AC15 Quota exhaustion | When approaching/exceeding free capacity, no upgrade/purchase/fallback paid request; document service pause/reset/recovery. User explicitly accepts loss of availability under free quotas. | Native policy evidence + simulated paused responses; no paid exhaustion test. Base/high scenarios require changed capacity/availability/budget, not hidden overage. |
| AC16 Latency/downtime | **P:** no planned outage; post-promotion outage recovery objective ≤5 min excluding provider-controlled transfer incident. **P:** static HTML p95 ≤2s across 20 authorized requests from a recorded Singapore vantage, excluding media/user-network variability; 4 MB original starts ≤3s in same controlled sample. | Record actual old/new measurements when authorized, network/browser/cache conditions, failed samples and transfer timings. No verified baseline or SLO yet. Failure → no promote/recovery; targets revised only with owner approval. Provider transfer can take 10s–10min per docs; never equate to guaranteed no downtime. |
| AC17 Backup/DR limits | No retention deletion. Owner records optional byte backup status and accepts lack of DR guarantee if none exists. A manifest/URL list alone is explicitly labelled not a byte backup. | Completeness/error/hash evidence for any backup actually made; synthetic restore to approved test store if backup/restore is chosen. No fake RPO/RTO; no production restore authorization inferred. |
| AC18 External lifecycle | Source/destination owners, same-store transfer prerequisites, domains/QR, token consumers, media-store fate, former Pro charges and integrations enumerated. Every manual exception has pre/post evidence and explicit approval. | Redacted owner/provider exports. No delete/merge/downgrade of shared team as automatic cleanup. No claim Git recreates external assets/accounts. |
| AC19 Trigger enforcement | Vercel Git/PR/deploy-hook and GitHub workflows/settings inspected before any push/merge. One CLI deploy path enforceable; alternative mutations blocked for release window. | Non-secret settings proof; prior 403 protection read resolved via owner export or recorded blocker. An empty ruleset list is insufficient. |
| AC20 Documentation | All required design, ADR, cost, cleanup, acceptance and implementation handoff documents link correctly; current handoff records approvals/commands/next task. Distinguish observed, inferred, proposed, mocked and live evidence. | Documentation-only link/diff/scope checks now; final implementation evidence maps every AC to pass/fail/blocked with reason. No unresolved blocking AC marked passed. |

No tests/CI currently exist. Propose a single `tests/` tree during authorized implementation for release contract/unit/browser tests; no competing tree or test source in `review/`. Use native Node for wrapper logic and existing browser tooling where suitable, not a speculative test-service subscription. A mock/stub proves control logic only, not actual Vercel permissions, quotas, billing, latency, storage continuity or live API costs.

Release requires explicit approvals plus every applicable criterion passed.
